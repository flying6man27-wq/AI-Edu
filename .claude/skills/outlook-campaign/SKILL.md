# 아웃룩 캠페인 — 발송하고, 회신을 회수한다

## 이 스킬이 다루는 범위

**여러 명에게 같은 요청을 보내고 → 각자 회신으로 파일을 보내오면 → 그걸 빠짐없이
모으는 것**까지가 목표다. 인사·교육 업무에서 반복적으로 나오는 형태다:
DX 과제 회수, 인사기록카드 회수, 동의서·서약서 취합, 설문 회신 수집.

```
① 캠페인 정의   현황 CSV 하나를 만든다 — 이게 전체 상태의 유일한 원본
② 환경 진단     outlook_probe.py — 데스크톱 COM 인지 웹인지 먼저 확정
③ 발송          초안 확인 → 승인 → 발송, CSV에 발송일 기록
④ 수집          받은편지함 스캔 → 첨부 저장 → CSV에 회신일·파일명 기록
⑤ 독촉          미회신자만 추려 2차 발송 (③을 다시 쓴다)
```

핵심 발상 하나: **현황 CSV가 곧 상태다.** 누구에게 보냈는지, 누가 회신했는지,
무슨 파일을 받았는지가 전부 한 파일에 있다. 그래서 중간에 며칠 끊겼다 돌아와도,
사람이 바뀌어도, CSV만 보면 이어서 할 수 있다. 별도 로그·메모를 만들지 말 것 —
상태가 두 군데 있으면 반드시 어긋난다.

## ① 캠페인 정의 — 현황 CSV

`assets/현황CSV_샘플.csv` 를 복사해 시작한다. 최소 컬럼:

| 컬럼 | 채우는 시점 | 용도 |
|---|---|---|
| `성명` `회사` `이메일` | 시작할 때 사람이 | 발송 대상 + 회신 매칭 키 |
| `이메일발송일` | ③ 발송이 실제로 나갈 때 자동 | 중복 발송 방지 |
| `회신일` `상태` `수집파일` | ④ 수집할 때 자동 | 회수 현황 |
| `비고` | 자동/수동 혼용 | 반송·특이사항 |

컬럼은 자유롭게 더 붙여도 된다. **본문 템플릿의 `{컬럼명}` 은 같은 행의 값으로
치환되므로, 사람마다 다른 내용(과제명·기한·담당자)은 컬럼으로 만들면 된다.**

`상태` 값은 이렇게 흘러간다:
`발송대기` → `발송완료` → `회신완료` / `회신(첨부없음)` / `반송`

### 명단은 어디서 오는가

이미 있는 명단을 쓰는 게 원칙이다. 새로 만들면 그 순간부터 원본과 갈라진다.
교육 관련이면 Google Drive 의 기존 시트(예: `_DX과제_신청현황`)가 이미 이 구조를
갖고 있는 경우가 많으니 먼저 찾아보고, 없을 때만 새로 만든다.

이메일 주소는 **추정하지 않는다.** 계열사마다 규칙이 제각각이라는 게 실측으로
확인돼 있다 — 한 곳은 `이름.성@도메인` 규칙이 일관되지만, 다른 곳은 이니셜 조합,
또 다른 곳은 닉네임을 쓰고, 개인 메일(네이버 등)이 섞인 경우까지 있다. 하나의
공식으로 맞힐 수 없다. 확실하지 않은 주소는 발송 전에 사용자에게 확인받는다.
추정으로 보내면 ④에서 반송으로 돌아오는데, 그때는 이미 기한이 며칠 지나 있다.

사내 메일 계정은 퇴사·이동 시 **승계**되기도 한다. 승계된 주소로 보내면 전임자
앞으로 안내가 가고, 교육 이수 기록이 뒤섞인다. 조직에 승계이력 대장이 있으면
발송 전에 대조할 것.

## ② 환경 진단 — 추측하지 말고 확인한다

```
python .claude/skills/outlook-campaign/scripts/outlook_probe.py
```

읽기만 하는 스크립트다. 데스크톱 Outlook COM 에 붙을 수 있는지, 계정이 몇 개인지,
받은편지함·보낸편지함에 접근되는지를 본다.

- **COM 연결 성공** → ③④를 스크립트로 그대로 진행. 이게 정상 경로다.
- **연결 실패** (맥·리눅스·웹 전용·pywin32 없음) → `references/web-fallback.md` 를 읽고
  그 경로로 간다. **웹은 발송만 자동이고 수집은 반자동**이라는 점을 사용자에게
  먼저 알릴 것. 이 제약을 모르고 시작하면 회수 단계에서 곤란해진다.

계정이 여러 개로 나오면 어느 주소로 나갈지 사용자에게 확인한다. 개인 계정으로
전사 안내가 나가는 사고는 되돌릴 수 없다.

## ③ 발송 — 초안을 먼저 본다

```
# 1) 초안 1건만 만들어 눈으로 확인
python scripts/outlook_send.py --csv 현황.csv --template 본문.html \
    --subject "[SECO] DX심화캠프 과제 안내" --limit 1

# 2) 확인됐으면 전체 발송
python scripts/outlook_send.py --csv 현황.csv --template 본문.html \
    --subject "[SECO] DX심화캠프 과제 안내" --send
```

`--send` 없이 실행하면 **임시보관함에 초안만** 만든다. 이게 기본값인 이유는
단순하다 — 메일은 취소가 안 되고, 20명짜리 오발송은 하루를 태운다. 초안 한 건을
사람이 열어보는 비용이 훨씬 싸다.

초안 단계에서는 CSV를 갱신하지 않는다. **실제로 나간 것만 기록에 남긴다** —
초안 만들어놓고 안 보낸 사람이 '발송완료'로 잡히면 그 사람은 영영 아무것도 못 받는다.

### 반드시 확인하고 넘어갈 것

- **치환 누락**: 스크립트가 `{성명}` 같은 미치환 자리표시자를 발견하면 발송을
  중단한다. CSV 컬럼명과 템플릿이 어긋났다는 뜻이다. 이걸 무시하고 보내면
  "{성명}님 안녕하세요" 가 그대로 나간다.
- **중복 발송**: `이메일발송일` 이 이미 찬 행은 자동으로 건너뛴다. 의도적으로
  다시 보내려면 `--resend`. 독촉은 이 옵션이 아니라 ⑤를 볼 것.
- **첨부**: 과제 양식 등을 함께 보내려면 `--attach 파일경로` (반복 가능).

### 발송 승인은 매번 받는다

사용자가 대상자를 콕 집어 "OO한테 보내"라고 했다면 그 사람에 한해 승인으로 본다.
명단 전체를 한 번에 보내라는 지시가 명확하지 않으면, 대상자 수와 명단을 보여주고
승인을 받은 뒤 진행한다. 보내기 전 Outlook **보낸편지함**에서 같은 제목·수신자로
이미 나간 게 없는지도 확인한다.

## ④ 수집 — 무엇이 잡히는지 먼저 본다

```
# 1) 미리보기 — 저장하지 않고 매칭 결과만 출력
python scripts/outlook_collect.py --csv 현황.csv --outdir 수집물 \
    --subject-contains "DX심화캠프" --dry-run

# 2) 확인됐으면 실제 저장
python scripts/outlook_collect.py --csv 현황.csv --outdir 수집물 \
    --subject-contains "DX심화캠프"
```

받은편지함을 훑어 발신자 주소를 명단과 대조하고, 첨부를 `{성명}_{회사}_원본명` 으로
저장한 뒤 CSV의 `회신일`·`상태`·`수집파일` 을 채운다.

`--dry-run` 을 먼저 돌리는 습관을 들일 것. 남의 이름으로 저장된 제출물은 나중에
아무도 못 고친다.

### 이 단계에서 실제로 터지는 문제 네 가지

스크립트가 이미 처리하고 있지만, **출력에 나오면 사람이 판단해야 하는 것들**이다:

1. **서명 로고가 첨부로 잡힌다.** 회신 메일마다 회사 로고 gif, 아이콘이 딸려온다.
   20명이면 순식간에 수백 개다. 스크립트가 Content-ID(인라인)와 40KB 미만 이미지를
   걸러내지만, 제출물이 정말 작은 이미지인 경우(예: 스크린샷 한 장)는 함께 걸러질
   수 있다. 수집 개수가 예상과 다르면 `--dry-run` 의 첨부후보 목록과 대조할 것.

2. **미매칭 회신** — 제목은 맞는데 명단에 없는 주소에서 왔다. 팀장이 대신 보내거나,
   개인 메일로 보내는 일이 흔하다. **버리지 말고 사용자에게 보고한다.** 본인 대신
   보낸 게 맞으면 해당 행의 이메일을 고치고 다시 실행하면 잡힌다.

3. **반송(NDR)** — 주소가 틀렸다는 뜻이다. `상태`가 `반송`으로 기록된다. 이걸
   '아직 회신 안 함'과 같이 취급하면 그 사람은 독촉만 계속 받고 메일은 계속
   허공으로 나간다. 반송이 나오면 주소부터 다시 확인한다.

4. **회신은 왔는데 첨부가 없다** — "곧 보내겠습니다" 이거나 본문에 링크로 낸
   경우다. `회신(첨부없음)` 으로 구분되니 본문을 열어 확인한다.

## ⑤ 독촉 — 미회신자만 추린다

④가 끝나면 미회신자 명단이 출력된다. 독촉은 같은 발송 스크립트를 쓰되,
**대상을 좁히고 본문을 바꾼다.**

```
python scripts/outlook_send.py --csv 현황.csv --template 독촉본문.html \
    --subject "[재안내] DX심화캠프 과제" \
    --only "a@x.com,b@y.com" --resend --send
```

`--only` 로 대상을 명시하는 게 안전하다. 이미 낸 사람에게 독촉이 가면 그 사람은
자기 제출이 누락된 줄 알고 다시 보내고, 그러면 중복 파일이 쌓인다.

독촉 본문은 처음 보낸 것을 그대로 재사용하지 말 것. 기한이 지난 상태라는 것,
이미 낸 사람은 무시해도 된다는 것을 한 줄 넣으면 문의 회신이 크게 준다.

## 다른 스킬과의 연결

- 수집한 파일이 **인사기록카드**면 → `seco-hrcard-converter` 로 넘긴다.
  이 스킬은 파일을 모으는 데까지고, 표준양식 변환·DB 등재는 그쪽 담당이다.
- **신규입사자 온보딩 안내**면 → `onboarding-notify` 가 대상자 확정·포털 등록까지
  포함한 전용 절차를 갖고 있으니 그쪽을 쓴다. 이 스킬은 회신을 받아야 하는
  캠페인용이다.
- 메일 본문 HTML을 새로 만들어야 하면 → `korean-html-typography` 와
  `seco-doc-identity` 를 적용해 사내 문서 표준을 맞춘다.

## 다루지 않는 것

- **대량 발송(수백 명)** — Outlook COM 은 건당 수백 ms가 걸리고, 사내 메일서버가
  스팸으로 볼 수 있다. 그 규모는 Apps Script 나 메일 솔루션이 맞다.
- **회신 본문의 내용 파싱** — 첨부 회수까지가 범위다. 본문에서 답변을 뽑아내는
  일은 케이스마다 달라 스크립트로 굳히면 오히려 틀린다.
